# Deploying the AHat backend on Render

The backend (FastAPI) runs on Render. The website stays on Vercel and forwards every `/api/...` request to Render, so the website and the API share one address and sign-in cookies work normally.

The demo staff and demo students stay in the database and keep working: with `DEMO_LOGINS=true`, accounts ending in `@ahatin.example` see their sign-in code (and staff their authenticator code) on screen. Everyone else receives codes by email only.

---

## Before you start

You need:

- the GitHub repository with this project (including `render.yaml` at the top level);
- a Render account (render.com), signed in with GitHub;
- the values from `backend/.env` on your computer (you will paste some of them into Render).

### MongoDB Atlas: allow Render to connect
Render's free plan has no fixed IP address. In Atlas → **Network Access** → **Add IP Address**, add `0.0.0.0/0` (allow from anywhere). The database is still protected by its username and password; use a strong password (see "After the first deploy").

### Backblaze B2: allow the live website to upload
In Backblaze → Buckets → `ahat-documents` → **CORS Rules**, add the live website address (for example `https://ahat-in.vercel.app`) next to `http://localhost:5173`, allowing `PUT` and `GET`, headers `content-type` and `x-amz-server-side-encryption`. Without it, students can't upload documents on the live site.

---

## 1. Create the service

1. Render dashboard → **New** → **Blueprint**.
2. Choose the repository. Render reads `render.yaml` and proposes one web service, **ahat-backend**.
3. Render asks for the secret values. Copy each one from `backend/.env`:

| Setting | Value |
|---|---|
| `APP_BASE_URL` | The live website address, e.g. `https://ahat-in.vercel.app` (no trailing slash) |
| `MONGODB_URI` | Same as in `backend/.env` |
| `FIELD_ENCRYPTION_KEY` | **Exactly** the value in `backend/.env`. It decrypts the staff authenticator secrets and passport numbers already in the database; a different value locks every staff member out |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Same as in `backend/.env` (Backblaze) |
| `RESEND_API_KEY` | Same as in `backend/.env` |
| `ADMIN_ALERT_EMAILS` | Who gets admin alerts, e.g. `info@ahat.in` (comma-separated for several) |

`SESSION_SECRET` and `OTP_PEPPER` are generated by Render automatically. Everything else (production mode, secure cookies, Backblaze bucket, email sender, Google Meet link, demo logins) is already set in `render.yaml`.

4. Click **Apply**. The first build takes a few minutes. When it finishes, open `https://ahat-backend.onrender.com/api/health`; it should show `{"status":"ok"}` (this also confirms the database connection).

If the service name is taken, Render adds a suffix (e.g. `ahat-backend-x1y2.onrender.com`). Then change the address in `frontend/vercel.json` (step 2) to match.

The backend refuses to start in production if a secret is missing or still a development value, and the Render log names the setting to fix.

## 2. Point the website at it

`frontend/vercel.json` already forwards `/api/...` to `https://ahat-backend.onrender.com`. Commit and push; Vercel redeploys the website. Leave `VITE_API_BASE_URL` empty in Vercel's settings so the website uses the forwarding rule.

## 3. Check it works

On the live website:

1. **Student:** Log in with `demo.student@ahatin.example`. The code appears on screen ("Fill it in").
2. **Staff:** Staff sign in → "Use" next to the counsellor → Continue → "Fill it in".
3. **Upload:** As the student, upload a PDF of 50–200 KB in Documents; as the counsellor, open it with **View**.
4. **Email:** Register with a real email address you own. The code arrives by email and is **not** shown on screen.

## Good to know

- **Free plan sleeps.** A free Render service stops after 15 minutes without visitors and takes about a minute to wake on the next visit. While asleep, the background jobs (sending queued emails, session reminders, deadline reminders, escalations) don't run. For real use, switch the plan to **Starter** in `render.yaml` (`plan: starter`) or in the Render dashboard.
- **Automatic deploys.** Every push to the main branch redeploys the backend.
- **Logs.** Render → ahat-backend → **Logs** shows requests and errors.
- **Demo data reset** is turned off in production.

## After the first deploy

- **Rotate the secrets shared in chat:** create a new Atlas database password and a new Resend API key, then update them in `backend/.env` and in Render → ahat-backend → **Environment**.
- **When the demo is no longer needed:** set `DEMO_LOGINS` to `false` in Render, and deactivate the demo staff in **Staff users**.
- **Virus scanning** of uploads is off until a ClamAV server is added (`CLAMAV_HOST`).
